# M0 evidence — 9 November 2026

- **Live bridge:** Windows, TTS 14.2.2, Steam build 22252224, fresh disposable Singleplayer Checkers. The External Editor API fetched the script list (one slot), installed a disposable Global marker handler with Save & Play, read its marker at X=-6, applied a named move, received an acknowledgement at X=6, then independently read X=6. A competing 39998 listener returned EADDRINUSE; after closing and rebinding the listener, a further read still returned X=6. The production Node probe also received its correlated `ok` callback. Connections use a TCP socket per message with EOF framing. This is a bridge spike, not a Signal Run match.
- **Desktop route:** On the same TTS build, desktop control navigated menus and identified pieces and legal destinations on built-in Checkers. Two attempted legal diagonal drags, one per colour, moved the cursor but neither piece. No turn exchange was completed. No paid API calls or manual interventions were used during these actions. This is a failed bounded test, not proof that every desktop interaction is impossible.
- **Fixture:** Original Signal Run rules are in `docs/signal-run.md`. Lua rules tests cover card effects, zero floor, turn order, winning, drawn final score and wrong seat. Further live game validation remains open.
- **Reuse decision:** The experimental upstream [tabletop-simulator-mcp](https://github.com/gosuni2025/tabletop-simulator-mcp) uses the same local External Editor API and offers a connection-status smoke test, generic object inspection and optional object actions. It describes visibility filtering as best effort and does not enforce game rules. Buddy uses a small independently written custom-message bridge so Lua can emit only seat-specific state and legal actions. No upstream code is copied. The spike above exercises a comparable connection, state-read and action/confirmation path, with an application-specific handler.
